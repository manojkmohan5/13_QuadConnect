================================================================================

The view marked GRADED for each of the four required kinds is the one wired to
the working URL listed beside it.

--------------------------------------------------------------------------------
KIND A1 - Function-Based View returning HttpResponse manually        [GRADED]
--------------------------------------------------------------------------------
  Name     : feedback_summary
  Owner    : Dhruv Thaker (dthaker3)
  URL      : /feedback/summary/          name="connect:feedback-summary"
  Model    : ExperienceFeedback
  Template : connect/feedback_summary.html, loaded with loader.get_template()
             and wrapped in HttpResponse (NOT render()).
  Purpose  : Aggregate private post-experience feedback into a single
             read-only summary - average rating, how many students opted in to
             stay connected, and which enjoyment factors came up most. Built
             with the manual HttpResponse path to show the request/response
             cycle without the render() shortcut hiding it.
  Status   : TODO - stub committed on main

4. NOTES FOR TEAMMATES
================================================================================

- Your build instructions are in docs/build_tasks/<yourname>_*.md. Read the
  whole file before writing code; it lists the exact files you may touch.
- DO NOT edit base.html. All four routes are already named and reversed there.
  If you think you need to change it, message the group instead.
- DO NOT edit another owner's section of views.py. The file is divided by
  commented section headers.
- entity_list.html is SHARED by Manojkumar and Prathamesh. Agree before
  changing its context contract; the contract is documented at the top of the
  file.
- First thing after cloning:
      cp .env.example .env
      python -c "from django.core.management.utils import get_random_secret_key as k; print(k())"
      # paste that into DJANGO_SECRET_KEY in your .env
      pip install -r requirements.txt
      python manage.py migrate
      python manage.py seed_demo_data
- db.sqlite3 is gitignored on purpose. Never force-add it: a tracked binary
  would conflict on every branch. seed_demo_data is idempotent, so re-run it
  instead of sharing a database file.

6. CHALLENGES & OPEN QUESTIONS
================================================================================

- BASE_DIR had to change from parent.parent to parent.parent.parent when
  settings became a package. It fails silently if you miss it: Django looks
  for db.sqlite3 one directory too deep and creates an empty one. Worth
  knowing if anyone restructures again.
- With DEBUG=False, runserver will not serve /static/. Our CSS is inline in
  base.html so production mode renders correctly today. The moment we add real
  static assets we need WhiteNoise or a collectstatic step - not before.
- UniqueConstraint cannot span relations, so "one match per student per week"
  is NOT enforceable in the model layer. It has to live in the matching
  service when we build it. Carried over from P1-A1.
- Still unspecified: the matching algorithm itself. compatibility_score and
  match_reason exist as fields but nothing computes them outside seed data.
  This is the biggest open design question for the next assignment.
