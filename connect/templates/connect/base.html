{% load static %} {% comment %} Site-wide base template for QuadConnect. Every page extends this. It owns the document shell, navigation, flash messages and footer; the visual design lives in static/css/quadconnect.css, loaded through {% static %} so production can serve it under a content-hashed filename (cache busting - see docs/notes/notes.txt). Blocks available to children: title text inside main_class optional class on <main>: "narrow" (sign-in pages), "reading" (long text) or "wide" (the home page, whose sections centre themselves) body_class optional extra class on <body>: " scene-page" puts the campus photo behind the page (sign-in pages) footer_extra optional last line of the footer (the photo's credit) page_header the whole page header; override to replace it (home does) heading the <h1> text, inside page_header subtitle optional line under the heading, inside page_header content the page body (required) extra_css optional per-page <link>/<style> scripts optional per-page <script> tags, at the end of <body> Navigation marks the current section with class="active". The list page itself gets aria-current="page"; its detail pages get aria-current="true", because the link then points at the section, not at the page being shown. Each link's icon is drawn by the stylesheet from its data-icon, so the link's text stays its whole content. Before login the navigation shows only Home, plus Log in and Sign up on the right; those pages are the only ones a visitor can open (P1-A5). After login the four sections appear, and the pages about QuadConnect itself (Feedback, Insights, Reports, API) sit behind "More", a <details>, so it opens without JavaScript. On a small screen the navigation is a tab bar along the bottom (body.has-tabs). Logging out is a POST form, so a link or a prefetch can never sign anyone out. Elements marked data-enter (or the first six items of a data-enter-list) fade in once, drawn by static/js/site.js with Motion.
